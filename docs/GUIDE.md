## 02. ОДИН СТРИМ. МНОГО ИСТОРИЙ.

Собираем конвейер, который помогает находить и выпускать сильные игровые моменты.

### Что делает система

Принимает разрешённый исходник, ищет кандидатов, собирает вертикальные ролики и ведёт очередь для нескольких каналов.

### Что определяет редактор

Контекст, понятность истории, права, бренд и качество. Автоматический балл помогает сортировать, но не доказывает виральность.

### Что находится в репозитории

Рабочее локальное ядро, девять реальных Git submodules с SHA pins, мост Medusa, inbox worker, инструкции подключения и примеры.

## 04. СТЕК ИЗ REELS ПО ДЕЛУ.

Доступный второй ролик - презентация пяти инструментов на чёрном экране с ведущим и титрами. Он не доказывает работу готового автопилота.

### WhisperX + PySceneDetect

Первый даёт речь и временные метки. Второй ищет смену изображения. Ни один сам по себе не знает, где лучший игровой момент.

### Auto-Editor + FFmpeg

Auto-Editor помогает убрать выбранные паузы. FFmpeg режет, масштабирует, сводит дорожки и кодирует результат.

### Remotion + наше ядро

Remotion нужен для сложных React-шаблонов. Ядро связывает входы, кандидатов, рендер и очередь. MVP рендерит через FFmpeg.

> Полный разбор доступности двух ссылок и границы наблюдений: docs/reference-analysis.md

## 05. НЕ СПИСОК ССЫЛОК. РАБОЧИЙ НАБОР.

Компоненты закрепляются на конкретных коммитах. Обновление становится отдельной проверяемой операцией.

### Забрать исходники целиком

Используй clone --recursive. Git submodule хранит точный коммит компонента и его оригинальную историю.

### Понять роль каждого

yt-dlp и TwitchAPI: источники; WhisperX: ASR; PySceneDetect: сцены; Auto-Editor: паузы; Remotion: оформление; FFmpeg: экспорт. Готовые clipping-движки - на следующей странице.

### Сверить версии и лицензии

Смотри upstream.lock.json и каталог upstream. Коммит фиксирует код, но не выдаёт права на стрим, музыку или бренд.

> Большие модели и бинарные зависимости устанавливаются отдельно. Они не помещаются в git.

## 06. НЕ ПИСАТЬ ВСЁ С НУЛЯ.

В набор входят готовые игровые и общие clipping-проекты. Их исходники закреплены отдельно от локального ядра.

### Medusa / игровой монтаж

Специализированный клиппер: игровой контент, blur-fit и facecam-композиции. AI-путь может отправлять текст и выбранные кадры внешнему провайдеру; это отдельный выбор и расходы.

### ClippyMe / второй маршрут

Дополнительный clipping-workflow. Его автопостинг использует внешний Zernio, а не встроенную локальную магию. Доступ, тариф и поддержку аккаунтов проверяй отдельно.

### Готовый мост Medusa

scripts/run_medusa.py проверяет права и передаёт локальный файл в закреплённый движок. По умолчанию LLM, ASR и обложки выключены; тяжёлая установка в этой поставке не прогонялась.

```sh
python3 scripts/bootstrap.py --profile medusa
.tools/medusa/bin/python scripts/run_medusa.py \
  examples/demo-source.mp4 \
  --config examples/config.json --source-id demo \
  --out output/medusa --clips 1
```

> --captions включает ASR; --allow-cloud разрешает внешний LLM. Подробнее: docs/upstream-selection.md

## 07. У КАЖДОГО СВОИ УСЛОВИЯ.

Открытый код не означает единую лицензию для всей системы и не решает права на исходные видео.

### Upstream остаётся upstream

Сохраняй copyright notices и LICENSE каждого компонента. Проектная лицензия локального glue-кода не заменяет условия подключённых репозиториев.

### Особые случаи

Medusa распространяется под AGPL-3.0; модификации и сетевое использование требуют отдельной проверки обязанностей. У Remotion собственные коммерческие условия.

### Бинарники и модели

Лицензия FFmpeg зависит от фактической сборки и GPL-компонентов. У ASR-моделей и сервисов могут быть отдельные условия, токены и стоимость.

> Перед распространением своего продукта проверь upstream.lock.json, notices и фактический состав сборки.

## 08. СНАЧАЛА ДЕМО. ПОТОМ GPU.

Базовый путь должен работать до подключения аккаунтов и тяжёлых моделей.

### Базовая среда

Рекомендуется Python 3.12 и FFmpeg/ffprobe. Bootstrap ставит ядро с Pillow в .venv; doctor показывает доступные фильтры и опциональные инструменты.

### Раздельные окружения

WhisperX и другие тяжёлые компоненты держи отдельно. Так конфликт CUDA, PyTorch или Python не ломает очередь публикаций.

### Проверка результата

Получить MP4 недостаточно: открой начало, границы склеек и финал. Проверь звук, субтитры, рекламную область и ffprobe. При отсутствии libass используется графический fallback; ASS хранится рядом.

```sh
git clone --recursive https://github.com/leoaic0nt3nt/vice-clip-factory.git
cd vice-clip-factory
python3 scripts/bootstrap.py --profile core
source .venv/bin/activate
viceclip doctor
```

> Точные команды полного bootstrap и установленный scope: docs/setup.md

## 09. ЗАПУСТИ ВСЮ ЦЕПОЧКУ.

Это конкретный smoke test: собственная синтетика, готовый JSON-транскрипт и один вертикальный ролик.

### Создать вход

Генератор пишет examples/demo-source.mp4. Это тестовый паттерн с синтетическим звуком, не игровой материал. Команда отказывается перезаписывать существующий файл.

### Получить проверяемый результат

run создаёт plan.json, ASS-субтитры и MP4. Открой ролик, сравни таймкоды и проверь result.json. Для повторного рендера выбери новую output-папку. Демонстрация не вызывает публикацию.

```sh
python scripts/make_demo.py
CLIP_INPUT=examples/demo-source.mp4
viceclip run --input "$CLIP_INPUT" \
  --source-id demo --config examples/config.json \
  --transcript examples/transcript.json \
  --top 1 --output-dir output/first-run
```

> PySceneDetect подключается отдельной командой viceclip scenes; базовый run не использует его автоматически.

## 10. НАЙТИ СТРИМ И ПОЛУЧИТЬ ФАЙЛ.

Это два разных этапа. Доступный публичный URL ещё не означает разрешение на использование.

### YouTube

Отслеживай разрешённые каналы через uploads playlist и API. Сохраняй video ID, автора, дату и статус прав. Не опрашивай весь поиск каждую минуту.

### Twitch

Helix помогает находить каналы, эфиры и клипы. Получение VOD/клипа и дальнейшее использование зависят от доступа и прав.

### Лучший вход для старта

Собственные записи OBS или партнёр, который даёт оригинальные файлы и письменное разрешение. Это быстрее и стабильнее случайного скрейпинга.

> Реестр источников: ID → автор → разрешение → файл → checksum → разрешённые платформы.

## 11. РАЗРЕШЕНИЕ ДОЛЖНО БЫТЬ ЯВНЫМ.

У стрима несколько слоёв прав. Согласие автора закрывает только те права, которыми он располагает.

### Стример и запись

Зафиксируй право скачивать, монтировать, публиковать, монетизировать и встраивать рекламу. Укажи каналы, срок и порядок отзыва.

### Издатель игры и музыка

Fan policy Rockstar описывает некоммерческое использование. Для коммерческого GTA-проекта отдельно проверь права издателя и музыкальные дорожки.

### Техническое правило

Пока подтверждения нет, источник остаётся в состоянии needs_permission. В коде нужны отдельные флаги разрешений и блокировка публикации.

> Разрешение стримера и прохождение платформенной модерации не гарантируют коммерческие права.

## 12. НЕ ПЕРЕСЧИТЫВАЙ ВЕСЬ СТРИМ.

Длинный материал сначала анализируется в лёгком представлении. Полное качество нужно на финальном отрезке.

### Сохранить один раз

Файл и хеш становятся неизменным источником. URL, ID и автор хранятся отдельно от приватных токенов.

### Сделать proxy

Аудио mono 16 kHz для ASR; уменьшенная картинка для сцен и движения. Не гоняй 4K через все модели.

### Кэшировать результаты

transcript.json, сцены и кандидаты привязаны к хешу исходника и версии алгоритма. Изменение шаблона не запускает ASR заново.

> yt-dlp используется только для источника с подтверждённым разрешением и доступом без обхода ограничений.

## 13. ОКНА, А НЕ БЕСКОНЕЧНОСТЬ.

Потоковая версия - следующий слой над проверенным файловым конвейером.

### Окна с перекрытием

Сохраняй разрешённый эфир небольшими блоками. Перекрытие сохраняет завязку события на границе файлов.

### Кандидат ждёт развязку

Не публикуй эмоциональный пик до окончания события. Добавь хвост после пика и дождись стабильного финала.

### Сначала измерить задержку

Считай время от события до готового MP4 и отдельно от MP4 до подтверждения публикации. Быстрый рендер не означает быстрый пост.

> Непрерывный захват эфира и webhook-сервис описаны как расширение; MVP работает с готовыми файлами.

## 14. УСЛЫШАТЬ И ПРИВЯЗАТЬ.

Нужны точные метки слов и реплик, чтобы монтаж и субтитры переживали склейки.

### Вход и выход

Передай аудио из proxy в WhisperX. Сохрани язык, segments и words. Диаризация нужна только если помогает разделить говорящих.

### Игровой словарь

Пополняй список имён, локаций, сленга и событий. Команда «за мной» и шум мотора должны интерпретироваться по контексту.

### Если речь плохая

Громкая игра, музыка и разговор поверх друг друга дают ошибки. Низкую уверенность отправляй на проверку; не придумывай пропущенные слова.

> Модели могут загружаться отдельно; диаризация может требовать Hugging Face token и принятие условий.

## 15. СКЛЕЙКА НЕ РАВНА СОБЫТИЮ.

Смена картинки помогает найти границы, но игра часто идёт одним непрерывным кадром.

### Что искать

Content/Adaptive detector отмечает заметные изменения. Это полезно для заставок, смены локаций и переключений камеры.

### Что не принимать за хайлайт

Чёрный экран, меню, загрузка и резкий поворот камеры могут давать сильный сигнал без интересной истории.

### Как использовать

Комбинируй сцены с речью, энергией звука и контекстом. Приоритет события определяется несколькими сигналами.

> MVP измеряет звук и межкадровое движение. PySceneDetect запускается отдельно: viceclip scenes INPUT --output-dir output/scenes.

## 16. ТИХО НЕ ЗНАЧИТ СКУЧНО.

Погоня, ожидание выстрела и напряжённое движение могут работать без речи.

### Консервативное удаление

Автоматически сокращай только подтверждённые пустые интервалы: меню, длинное бездействие, ожидание соединения.

### Запас вокруг речи

Оставляй небольшие поля до и после слов. Не режь вдох, начало реакции или звук игрового события.

### Карта исходного времени

Сохраняй kept_ranges. После каждой склейки пересчитай титры, музыку, рекламный тайминг и итоговую длительность.

> Паузы сокращаются консервативно с учётом движения. После отдельного viceclip autocut пересоздай транскрипт.

## 17. БАЛЛ С ОБЪЯСНЕНИЕМ.

Каждый кандидат должен отвечать на вопрос: что здесь произошло и почему зрителю стоит досмотреть?

### Сигналы

Реакция автора, слова о неожиданном событии, всплеск звука, изменение картинки и достаточный контекст.

### Штрафы

Реклама исходного стрима, загрузки, повторы, клиффхэнгер без развязки, непонятная завязка и почти одинаковые окна.

### Честная граница MVP

Встроенный ранкер - эвристика. Он не распознаёт все игровые события и не предсказывает просмотры. Для этого нужен размеченный набор и модель.

> Храни evidence и confidence рядом со score. Один громкий крик не должен выигрывать автоматически.

## 18. ШЕСТЬ ПРОВЕРОК ПЕРЕД ВЫПУСКОМ.

Первые ролики проходят ручную приёмку. Автоматизация растёт вместе с подтверждённым качеством.

### История

За 1-2 секунды понятно, что происходит? Есть развязка? Заголовок совпадает с событием?

### Картинка и звук

Виден герой, маршрут и важный HUD? Речь разборчива? Текст не закрывает действие? Нет обрубленных слов?

### Права и публикация

Источник разрешён, музыка проверена, аккаунт выбран верно, реклама согласована и пост не является дублем.

> Любой критический провал = вернуть на монтаж. Общий высокий балл не компенсирует отсутствие прав.

## 19. КРЮЧОК. СОБЫТИЕ. ФИНАЛ.

Стартовый монтажный рецепт: 20-45 секунд, если событие действительно укладывается в этот хронометраж.

### 00:00-00:02 / обещание

Один конкретный вопрос или необычный факт в кадре. Например: «Он выбрал самый плохой момент для побега».

### 00:02-00:30 / развитие

Убирай повторяющуюся информацию, сохраняй причинность. Дай зрителю увидеть выбор, препятствие и попытку.

### Последние секунды / развязка

Покажи исход. Заверши на реакции или ясной точке. Петля допустима, если она не скрывает финал.

> Хронометраж - редакторская гипотеза для теста, а не универсальное условие алгоритма площадки.

## 20. СОХРАНИ САМУ ИГРУ.

Автокроп по центру может обрезать цель, миникарту и второй автомобиль.

> Макеты схематические. В примерах нет кадров GTA VI и имитации реального геймплея.

## 21. КРУПНО. КОРОТКО. ВОВРЕМЯ.

Текст помогает понять реакцию, а не конкурирует с игровым интерфейсом.

### Реплика вместо простыни

Один короткий смысловой фрагмент, обычно до двух строк. Для быстрого текста сокращай фразу редакторски, сохраняя смысл.

### Точный тайминг

Сначала карта склеек, затем перевод исходных меток в время ролика. Слова внутри удалённого интервала не должны остаться в титрах.

### Контраст и безопасные зоны

Крупный светлый grotesk на тёмной подложке или с обводкой. Проверь на телефоне и в реальном интерфейсе обеих площадок.

> В MVP ASS-субтитры строятся из JSON-транскрипта. Полный ASR устанавливается отдельно.

## 22. РЕКЛАМЕ НУЖНО СВОЁ МЕСТО.

Верхняя или нижняя полоса настраивается отдельно от игрового слоя и субтитров.

### Шаблон кампании

ID кампании, текст, ссылка, период, разрешённые аккаунты и площадки. Один ролик не должен случайно получить старый оффер.

### Макет

Одна статичная полоса, узнаваемый стиль, читаемый текст. Не закрывай миникарту, прицел, реакцию автора и платформенные кнопки.

### Ограничения

Маркировка и paid promotion настройки зависят от страны и площадки. В РФ реклама в Instagram запрещена; такой маршрут по умолчанию выключается.

> Сначала коммерческие права на игру и запись. Рекламный баннер сам по себе этих прав не создаёт.

## 23. СКОРОСТЬ НАДО ИЗМЕРЯТЬ.

Быстрый режим - результат профилирования, кэша и ограниченного числа финальных рендеров.

### Базовый экспорт

1080×1920, H.264, AAC, 30 fps, yuv420p, faststart. Проверь фактические требования площадки при обновлении API.

### Аппаратный кодировщик

VideoToolbox на Mac или NVENC на совместимом GPU могут ускорить экспорт. Сравни качество и размер с CPU-режимом.

### Тест на своём железе

Замерь source duration / processing time, p50/p95 и размер файла. Сначала proxy и top-N отбор, потом только финальный рендер.

> Remotion - для сложных графических шаблонов. Перед коммерческим использованием проверь актуальную лицензию.

## 24. КАЖДОМУ КАНАЛУ СВОЙ ДОСТУП.

Загрузка идёт через официальный Data API и OAuth пользователя, который управляет конкретным каналом.

### Подключение

Создай Cloud project, включи YouTube Data API, настрой OAuth consent и запроси минимально необходимый upload scope.

### Проверить владельца

После авторизации сопоставь channel ID с ожидаемым каналом. Для каждого канала храни отдельную привязку и refresh token.

### Подтверждение

Используй resumable upload. Сохрани video ID и статус. Принятие upload не подтверждает обработку и воспроизведение у зрителя; это отдельная проверка.

> Квоты и правила API меняются. Текущие ограничения смотри в docs/platform-research.md, а не в старом Reels.

## 25. СНАЧАЛА КОНТЕЙНЕР. ПОТОМ REEL.

Официальная публикация требует подходящего профессионального аккаунта, разрешений и доступного медиа.

### Настройка приложения

Выбери поддерживаемый login flow и scope для публикации. Для внешних клиентов могут требоваться App Review и расширенный доступ.

### Подготовка файла

Для URL-based пути ролик должен быть доступен Meta по HTTPS. Локальный путь на компьютере не является публичным video_url.

### Жизненный цикл

Создай REELS container, опрашивай status_code, дождись готовности и только потом вызывай media_publish. Сохрани media ID.

> Sponsored Instagram jobs заблокированы до проверенного partnership flow. Лимиты и токены требуют отдельной проверки.

## 26. ОДНА ФАБРИКА. РАЗНЫЕ РЕДАКЦИИ.

Каналы отличаются аудиторией, языком и подачей. Копирование одного файла во всю сеть - слабая стратегия.

### Профиль канала

Язык, темы, тон заголовков, бренд, часовой пояс, расписание, допустимые кампании и отдельный OAuth-доступ.

### Маршрутизация

Кандидат назначается подходящему аккаунту. Одинаковые события в близких роликах объединяются до постановки в очередь.

### Ресурсы и квоты

Общий лимит проекта API и лимит аккаунта - разные вещи. Храни резерв, учитывай очередь и останавливай отправку при ошибках авторизации.

> Название аккаунта в интерфейсе не подтверждает его channel ID или Instagram user ID.

## 27. НЕ ДУБЛИРУЙ НЕИЗВЕСТНЫЙ РЕЗУЛЬТАТ.

Публикация - операция с побочным эффектом. Повторять её вслепую опасно для канала.

### Уникальный ключ

Хеш ролика + платформа + account ID. Очередь не создаёт второй такой job при повторном запуске.

### Явные состояния

pending → approved → uploading. Успешный ответ даёт uploaded для YouTube или published для Instagram. Неоднозначный ответ даёт unknown и требует сверки.

### Повтор только после проверки

Ошибка до отправки может быть повторяемой. После неизвестного результата ищи уже созданный ресурс. Нужны remote ID, журнал и временные метки.

> Dry-run по умолчанию. Состояние approved и явный --execute нужны для реального внешнего действия.

## 28. СМОТРИ НА УЗКИЕ МЕСТА.

Система должна объяснять, почему файл не стал опубликованным роликом.

### Журнал

source ID, clip ID, версия плана, account ID, статус, external ID и код ошибки. Секреты и подписанные URL в лог не попадают.

### Сигналы для оператора

Нет места на диске, истёк токен, недоступен исходник, отказ API, зависший контейнер, отсутствие разрешений или провал QA.

### Восстановление

Отдельно копируй базу очереди, конфиги без токенов и реестр прав. Проверяй восстановление до запуска сетки каналов.

> Неизвестная публикация не исчезает из отчёта. Она остаётся задачей для оператора.

## 29. ОТ ДЕМО ДО INBOX WORKER.

Постоянная фабрика получает разрешённые локальные файлы и последовательно увеличивает степень автоматизации.

### Уровень 1 / локально

Синтетика → анализ → MP4. Без внешних API и тяжёлых моделей. Это проверяет монтажное ядро.

### Уровень 2 / с редактором

watch_inbox.py ждёт стабильности файлов, хеширует их и не обрабатывает повторно. Один worker относится к одному источнику прав. В YouTube очередь добавляются выбранные аккаунты из automation.

### Уровень 3 / после настройки

Для auto-approval нужны automation.auto_approve=true и --auto-approve. Только --execute включает внешнюю отправку. Instagram требует отдельного публичного media URL для каждого файла.

```sh
mkdir -p data/inbox
python scripts/watch_inbox.py \
  --inbox data/inbox --config config.local.json \
  --source-id your-owned-source --once
```

> Доставка через атомарное переименование. Боевой автозапуск здесь не установлен. Инструкции: docs/operations.md

## 30. ДОХОД НЕ РАВЕН ПРОСМОТРАМ.

Модель начинается с разрешённых способов монетизации и стоимости выпуска.

### Себестоимость

Обработка + хранение + трафик + ручная проверка + доля автора + поддержка. Раздели постоянные и переменные расходы.

### Рабочие источники дохода

Услуга монтажа владельцам контента, разрешённые интеграции и доход платформы при выполнении её условий. Спонсорство требует собственных прав.

### Пример расчёта, не прогноз

100 роликов × 40 ₽ переменных затрат = 4 000 ₽. При 10 000 ₽ выручки и 8 000 ₽ постоянных расходов итог -2 000 ₽.

> Изменённые титры и рамка не гарантируют одобрение YouTube reused/inauthentic content monetization.

## 31. СЕМЬ ДНЕЙ НА ПЕРВУЮ ПЕТЛЮ.

Проверяем одну рабочую цепочку на разрешённом материале до подключения новых каналов.

### Дни 1-2 / основа

Собрать права, клонировать компоненты, пройти doctor, выпустить демонстрационный MP4 и один реальный тестовый монтаж.

### Дни 3-4 / качество

Разметить 30-50 моментов, сравнить кандидатов с редактором, настроить паузы, титры, hook и шаблон.

### Дни 5-7 / доставка

Подключить один аккаунт каждой доступной площадки, проверить приватный/тестовый сценарий, подтвердить external ID и собрать первые метрики.

> Публикация GTA VI возможна после появления разрешённых материалов. Дата официального релиза на момент гайда: 19.11.2026.

## 32. ОДИН БРИФ ДЛЯ АГЕНТА.

Передай этот запрос вместе с репозиторием. Дальше агент должен показывать доказательства каждого шага.

### Запрос

«Собери серию вертикальных игровых роликов из разрешённых источников. Начни с реестра прав и одного тестового файла. Используй закреплённые upstream-компоненты, сохраняй таймкоды и промежуточные результаты.

### Требования

Отбирай понятные истории с развязкой. Не удаляй тихую игровую сцену только по уровню звука. Сохраняй важный HUD, пересчитывай титры после склеек и проверяй рекламу по кампании.

### Условия выпуска

Для каждого аккаунта веди отдельный доступ и очередь без дублей. До выпуска покажи top-N, причины выбора и QA. Отчитайся MP4, планом монтажа, журналом и external ID. Не называй dry-run публикацией».

> Полные конфиги, команды и критерии расширения находятся рядом с кодом в docs/.
